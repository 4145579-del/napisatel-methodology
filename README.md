# Методическое ядро Написателя

Рекомендации и задания для подготовки научной статьи по материалам исследования. Этот репозиторий служит централизованным источником обновлений для локального приложения «Написатель».

Выпуск 1.0.0 содержит методический комплект НС 1.0 от 6 ноября 2026 года и 40 заданий. Рукописи, исходные данные, пользовательские правила и учетные данные модели в репозиторий не входят.

## Состав

| Файл | Назначение |
|---|---|
| `methodology/instruction.md` | Самостоятельная инструкция для модели |
| `methodology/prompts.json` | Задания этапов |
| `compatibility.json` | Формат пакета и совместимость с исполнителем этапов |
| `CHANGELOG.md` | История изменений |
| `docs/latest.json` | Последний подписанный выпуск для загрузки приложением |
| `docs/release-1.0.0.json` | Неизменяемый файл первого выпуска |
| `docs/public-key.pem` | Открытый ключ проверки подписи |
| `scripts/release.mjs` | Проверка и подготовка следующих выпусков |

## Подключение к приложению

После включения GitHub Pages папка `docs` становится источником файлов обновления. В настройках Pages нужно выбрать публикацию из ветки `main`, папки `/docs`. Адрес пакета после включения Pages – `https://4145579-del.github.io/napisatel-methodology/latest.json`. Открытый ключ доступен по адресу `https://4145579-del.github.io/napisatel-methodology/public-key.pem`.

1. Откройте в «Написателе» раздел «Методика и обновления», затем «Источник обновлений».
2. Укажите HTTPS-адрес `latest.json` и содержимое `docs/public-key.pem`, полученное от издателя через доверенный канал.
3. Нажмите «Сохранить источник и проверить».
4. Оставьте включенной проверку при запуске, чтобы получать новые выпуски автоматически.

Открытый ключ подписи предназначен только для проверки методики. Он не дает доступа к ИИ и может распространяться вместе с приложением. Секретный ключ подписи хранится у издателя отдельно от этого репозитория.

Обновления применяются к новым проходам. Начатая подготовка продолжает использовать закрепленную версию методики. Локальные правила автора сохраняются отдельно и при обновлении не изменяются. Если сеть недоступна или подпись не подтверждена, приложение сохраняет предыдущую установленную версию.

## Подготовка следующего выпуска

Для средства выпуска нужен Node.js 24 или новее. Дополнительные пакеты устанавливать не требуется.

1. Измените исходные рекомендации или задания и дополните `CHANGELOG.md`.
2. Подготовьте выпуск с новым номером версии и возрастающим порядковым номером. Передайте путь к секретному ключу издателя, который находится вне репозитория.

   ```sh
   node scripts/release.mjs pack --key /путь/к/signing-private.pem --version 1.1.0 --sequence 2
   ```

3. Проверьте подпись, соответствие исходным материалам и состав пакета.

   ```sh
   node scripts/release.mjs verify
   ```

4. Сохраните изменения в Git и передайте их в репозиторий. После обновления GitHub Pages новый `latest.json` станет доступен приложениям авторов.

Предыдущие файлы `release-*.json` сохраняются. Один номер выпуска не используется для разных текстов. Изменение программной логики этапов требует согласованного обновления приложения и `compatibility.json`; этим каналом приложение не загружает исполняемый код.

## Подпись и проверка

Пакет содержит поля `payload` и `signature` в Base64. Подпись Ed25519 относится к точным байтам содержимого `payload`. Внутри находятся версия, порядковый номер, дата выпуска, описание изменений, признак совместимости, инструкция и задания. Подпись подтверждает происхождение пакета. Содержательную проверку методики выполняет издатель.

Секретный ключ, файлы `.env`, рабочие базы и материалы исследований не должны попадать в коммиты. При потере ключа требуется отдельное обновление доверенного открытого ключа у пользователей.
